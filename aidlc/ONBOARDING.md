# AI-DLC in gc-harness

This repo is configured for [AI-DLC](https://github.com/awslabs/aidlc-workflows),
a staged software-delivery workflow that runs inside Claude Code via `/aidlc`.
It is **opt-in by invocation** — nothing changes until you run it.

The engine is pinned in `.aidlc-version`. Read `aidlc/ACTIVATION.md` for when
it is worth using; this file is setup only.

## Setup

```bash
curl -fsSL https://github.com/awslabs/aidlc-workflows/releases/latest/download/install.sh | sh
```

Installs a per-user binary at `~/.local/bin/aidlc` (~114 MB of runtimes under
`~/.local/share/aidlc`). No sudo, no Bun, no Node.

### Make `aidlc` visible to Claude Code's hooks

Required, not optional. The AI-DLC hooks wired in `.claude/settings.json` run in
a **non-interactive** shell whose PATH does not include `~/.local/bin`. If
`aidlc` is not resolvable there, every hook fails silently and the workflow
stalls with no error.

```bash
aidlc config runtime --show        # the `aidlc:` row must say `found`
```

If it says `interactive-only`, put the binary somewhere already on the system
path:

```bash
ln -sf ~/.local/bin/aidlc /opt/homebrew/bin/aidlc
aidlc config runtime --show        # re-check
```

### Materialise the engine (required after every clone)

The engine tree under `.claude/` is **not committed** — it is regenerated from
the pinned version, so the repo carries ~1k lines of config instead of ~163k
lines of vendored engine source.

```bash
cd <repo root>
aidlc config --harness claude      # writes .claude/ from the pinned 2.8.1
aidlc doctor                       # expect: 0 problems
```

Then open Claude Code and run `/aidlc --doctor`.

## Using it

```text
/aidlc <describe the work>
```

Scope is auto-detected and you confirm it; the workflow stops at approval gates.
`/aidlc --status` shows position, `/aidlc --help` full usage. Artifacts land in
`aidlc/spaces/default/intents/<record>/`.

## Shared vs. local

| Path | State |
| --- | --- |
| `.aidlc-version` | Committed — the engine pin |
| `.claude/settings.json`, `aidlc/*.md` | Committed — wiring and the activation gate |
| `aidlc/spaces/**` | Committed — workspace records |
| `.claude/` engine tree | Not committed — regenerated by `aidlc config` |
| `.claude/settings.local.json` | Local, gitignored |

## Two deliberate deviations

**1. No Amazon Bedrock pins.** AI-DLC ships an `env` block setting
`CLAUDE_CODE_USE_BEDROCK=1`, `AWS_REGION`, and Bedrock model ARNs. Removed, so
Claude Code uses whatever auth is configured.

**2. No `statusLine` override**, so the personal statusline survives.

Both live in `.claude/settings.json`, which therefore no longer matches the
bytes AI-DLC ships. **Any `aidlc config ...` command reports a conflict on that
file and needs `--force`, which puts both back.** Re-strip afterwards:

```bash
aidlc config <...> --force
aidlc-postconfig .        # local helper; or edit the env/statusLine keys out by hand
```

Symptom if you forget: Claude Code fails with `Could not load credentials from
any providers` — it is trying Bedrock with no AWS credentials. Fix the file,
then **restart the session** (Claude Code reads `env` only at session start).

Unlike the shared team repos, `Edit`, `Write`, and `Task` are left in
`permissions.allow` here: this is a single-owner repo, so there is no one else
whose write prompts would be silently disabled.
